# 评测协议

[English](evaluation.md) | **简体中文** · [文档目录](README_zh.md)

本实现遵循 [TAG-Bench arXiv v2 第 4 节](https://arxiv.org/html/2609.01542v2#S4)和作者提供的 `compute_miou.py`。对于基准中时长为正的目标区间，可复现原始汇总结果。代码不包含特定工作站的硬编码目录。

## 区间集合

标准时间戳以秒为单位，例如 `1.20s~3.40s;8.00s~9.50s`。指标计算模块也接受 `[[1.2, 3.4], [8.0, 9.5]]`。端点必须为有限的非负数，且满足起点 ≤ 终点。真实标注区间的时长必须为正；预测则可以是零时长的时间点。

计分、计数和计算中点误差前，会分别合并预测与标注中**重叠或端点相接**的区间。预测不会按录音时长裁剪。历史自由文本解析器会拒绝终点达到或超过 12 小时的区间；直接输入标准区间时没有这一解析上限。

设合并后的预测集合为 H、目标集合为 G：

- `IoU = duration(H ∩ G) / duration(H ∪ G)`。
- `gIoU = IoU − (duration(C) − duration(H ∪ G)) / duration(C)`，其中 C 是同时覆盖 H 和 G 的最小单一区间。
- 单条查询的中点 MAE：对每个合并后的目标区间，计算其中点到最近预测中点的距离，再对所有目标求平均。一个预测可以匹配多个目标，不进行一对一的二分图匹配。
- 计数准确率比较合并后的预测区间数和目标区间数。漏报率与多报率分别使用 `<` 和 `>` 判断。

论文中的计数公式使用标注的 GT 区间数。基准标注中不存在会改变计数的重叠，历史代码则对预测和标注两侧都进行合并。本版本遵循该可执行实现。

## 汇总与空预测

所有指标对每条查询赋予相同权重，不按音频时长或目标区间数加权。整体 mIoU 不是八个子集分数的等权平均。Recall 的阈值判断包含等号：`IoU >= threshold`。

| 空预测的计分方式 | 取值 |
| --- | --- |
| IoU | 0 |
| Recall@0.3、0.5、0.7 | 未命中 |
| gIoU | −1 |
| 预测区间数 | 0 |
| 中点 MAE | `null`，不参与 MAE 均值计算 |

`MAE_Cvg` 表示进入中点 MAE 均值计算的查询比例。在本基准中，`parse_failure_rate = 1 − MAE_Cvg`。使用 `--missing empty` 补入的缺失记录也计入空预测比例；`audit.json` 会区分未收到的记录和已经收到但无法解析的回答。

JSON 中的得分按小数保存，gIoU 可以为负；MAE 单位为秒，区间数保留实际计数。按照论文形式展示时，将重叠指标、召回率、覆盖率和计数相关比例乘以 100。汇总前不对数值进行舍入。

## 历史解析器兼容性

`legacy_parser.py` 保留了作者提供的确定性级联解析规则，支持区间分隔符、起止时间描述、方括号数组、时钟格式、孤立时间点，以及可选的英文数字词转换。`parsing.py` 为对应模型 ID 应用原有的思考段、结论段和数字词处理配置。

历史级联规则较为宽松：可以将裸数字配对、交换两个孤立时间点的顺序，或者在抽取的结论段没有可用区间时退回解析完整回答。这些规则可能从自由文本中提取到无关数字。保留它们是为了复现历史处理过程，并不代表对语义进行了核验。对于格式可控的新输出，建议使用标准区间字符串或数组，并指定 `--parser strict`。

与原解析器一致，历史规范化会把恢复出的端点舍入到小数点后两位。严格模式只校验输入的标准区间，不进行这一量化。

只有字面值为 **`0s~0s`** 的标准化字符串才是历史失败哨兵，判断时忽略首尾空白。**`0.00s~0.00s` 则是实际的时间点预测。** 对时长为正的 GT，它的 IoU 为零，但仍贡献一个预测区间和一个中点。这一区别会影响 gIoU、MAE、覆盖率和计数指标。新 API 也支持用空字符串、空列表和 `null` 明确表示空预测。

`normalize` 和 `run` 用于解析原始回答；`evaluate` 直接读取标准区间。复现时，应使用 `evaluate` 或 `reproduce_paper.py` 对历史标准化文件计分，不应再次经过自由文本解析器。

## 覆盖情况

`run` 会根据提供的标注集检查预测。默认情况下，缺失记录会报错。`--missing empty` 对完整标注集进行评测；`--missing skip` 只评测匹配到的记录，并记录缺失 ID。未知或重复的预测始终会报错。

`evaluate` 接受自身包含预测和 GT 的配对记录，并只评测实际存在的行。它无法推断基准中缺失的记录。论文复现脚本有意使用这一模式：Gemini 的历史文件有 1,749 行，补入缺失项会改变原始分数。

回归测试与外部结果比对的相关说明见[论文来源与复现说明](paper-provenance_zh.md)。
